# v0.1 hardening and release checklist

The driver still bootstraps directly with stable rustc. No required build or test
fetches dependencies or calls Cargo. Qt validation is opt-in for ordinary builds:
configure with `-DRPP_ENABLE_QT_VALIDATION=ON` for the required release workload.
Provide `RPP_TEST_RUSTC` and `RPP_TEST_CMAKE` explicitly when running CTest.

## Correctness changes

Static archives now contain `rpp-runtime/` with a `rpp-runtime-v1` record. Install
only the archive; remove old explicit `.runtime` install rules. Legacy sidecars
remain readable. This fixes loss of runtime information after deleting an
untracked sidecar. Ordered native arguments and duplicates are retained.

Driver outputs are staged beside their destinations and published after success.
Failure diagnostics and subprocess status are retained. Builds of the same tree
must not be launched concurrently; normal parallel target builds are supported.
Compiler selection is fingerprinted at configure time and rustup selections are
pinned when the sysroot contains an identical compiler. Changing the selected
compiler requires a fresh build directory. Native builds only are supported.

## Qt notes example

`examples/qt-notes` uses Qt Widgets, AUTOMOC, two local Rust crates, and system
SQLite. Configure it like the other examples with installed Rpp modules. Run
`ctest` for the offscreen persistence/CRUD test or launch `RppNotes` interactively.
All link declarations use `SQLite3::SQLite3`; CMake 3.25 gets a compatibility alias.

The C ABI in `notes.h` uses opaque single-threaded handles and borrowed UTF-8
views. List callbacks borrow row data only for their duration and cannot re-enter
the backend. Rust owns error allocations; release each with `notes_free` exactly
once. C++ uses RAII for both handles and errors. C++ exceptions are contained in
callbacks, and exported Rust operations contain unwinding panics. Invalid/dangling
foreign pointers, double frees and aborting panics remain outside that contract.
The example ABI is not a long-term compatibility commitment.

`tests/qt_notes.py` builds Debug/Release with all three generators, relocates tools
and the backend, removes producer source/build trees, then builds a separate
non-Qt C++ ABI consumer using installed headers and package exports. No producer
files are available to that consumer. System Qt and SQLite remain external.

## Recorded validation

[Committed-source matrix](baselines/v0.1-hardening-installed-matrix.json): CMake
3.25.0 and 4.4.5 × Rust 1.96.0 and 1.97.1 passed all five CTest gates, including
Qt/SQLite and isolated installed consumption on all three generators. The source
revision and clean-tree status are recorded in the report. This is installed-tool
coverage, not the required minimum/current Rust release matrix. Known blockers
are listed explicitly in the report; `release_ready` is false.

## Required release evidence

Run `tests/release_gate.py --help` for the five explicit installed-tool roles.
Use CMake 3.25.0 and current stable, Rust 1.85.0 and the latest two stable release
lines. Select current stable versions from release announcements when preparing
the release; the harness deliberately does not query networks or update tools.
Missing tools produce a blocked report, not a pass. The matrix uses matching
CMake/CTest binaries and requires Qt validation. JSON report schema is version 1.

- [ ] Minimum/current CMake × minimum/previous/current stable Rust passes.
- [ ] Every cell passes Ninja, Makefiles, Multi-Config and Debug/Release.
- [ ] Core recovery, no-op and isolated installed-consumer regressions pass.
- [ ] Qt offscreen tests and manual visual smoke check pass.
- [ ] Toolchain errors are actionable; no required cases are silently skipped.
- [ ] Baselines are remeasured after correctness fixes, without timing thresholds.
- [ ] Licensing and offline reproduction instructions reviewed.

## Remaining limitations and release blockers

Rust 1.85.0, 1.99.1 and 1.100.0 are now installed. The older 1.96/1.97
reports remain historical, not substitutes for the release matrix. Current release
reports, benchmark evidence and approval status are stored beside the candidate
archive; see [the release procedure](release-procedure.md). No tool is downloaded
automatically. A candidate is not approved merely because its archive exists.

The former `v0.1/depfile-loss` blocker is resolved. Make now tracks each Rust
depfile as an object co-output and regenerates both when the depfile disappears.
See [root cause, fix and regression evidence](depfile-loss.md). The previous
validation report above remains historical; the new focused matrix verifies this
fix without claiming overall v0.1 release readiness.

The expanded suite covers module renames, include_str/include_bytes inputs,
depfile-loss recovery, final-link failure recovery, compile-error recovery and deletion of staged/published
rlibs, staticlibs and executables. Injected compiler, linker and archiver failures verify preservation of previous
outputs, cleanup of staged files and exit status. Release hardening adds controlled process interruption and retries, response-file
publication checks, GNU/LLVM archive consumption and the versioned path audit.
The user reported successful visual adding/editing/deleting, restart persistence
and resizing on 2026-11-12; this is a human observation, not an offscreen result. Automatic environment-variable dependency tracking
is not provided: explicitly reconfigure/rebuild when changing such inputs.
Cross-compilation, other operating systems, shared Rust libraries, preprocessing,
registries, procedural macros and automatic header imports remain deferred.


## Supported path limits

The path audit passes spaces, Unicode, apostrophes and dollar signs across all
three generators on CMake 3.25.0 and 4.4.5. CMake 3.25.0 rejects `#` in custom
command outputs during generation; 4.4.5 accepts the tested paths. Double quotes
in source/build directory names fail stock CMake compiler-probe parsing in both
versions. These paths are outside v0.1 support and fail configuration rather than
silently building stale artifacts. Run `tests/path_audit.py --help` to reproduce.
